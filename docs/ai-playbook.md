# AI를 가장 잘 쓰는 사람들의 습관 → GO PLACE에 적용

(2026-11-22 대표 질문: "AI를 가장 생산적으로 쓰는 사람들은 어떻게 쓰나? 나도 배워서 적용하고 싶다")

## 0. 출처와 주의

- 공개된 글을 바탕으로 정리했다: Anthropic 엔지니어링 블로그 "Claude Code 모범 사례"·"Anthropic 팀들은 Claude Code를 어떻게 쓰나"(2025),
  Claude Code를 만든 Boris Cherny가 공개한 작업 방식, 전 OpenAI 연구자 Andrej Karpathy의 "컨텍스트 엔지니어링"·"Software 3.0" 강연(2025), OpenAI Codex 사용법(AGENTS.md).
- **확인된 것**: 이 사람들이 이렇게 한다고 스스로 공개한 내용. **가설**: 그대로 따라 하면 우리도 같은 효과가 난다는 것 (우리 상황은 휴대폰·혼자·비개발자라 다르다).
- 원문은 오늘 다시 열어 보지 않고 기억으로 정리했다. 세부 숫자보다 **원리**를 보라.

## 1. 핵심 한 문장

> 잘 쓰는 사람은 AI에게 **"일"을 시키는 게 아니라 "일하는 환경"을 만들어 준다.**
> 환경 = 기억(규칙 문서) + 확인 수단(테스트·화면) + 반복 도구(스킬·예약 작업) + 사람의 판단.

AI는 매번 기억을 잃고 새로 시작하는 아주 똑똑한 신입이다. 신입이 잘하게 하는 법은 사람과 똑같다:
업무 매뉴얼을 주고, 결과를 확인할 방법을 주고, 실수하면 매뉴얼을 고친다.

## 2. 일곱 가지 습관

| # | 습관 (잘 쓰는 사람) | 왜 효과가 있나 (원리) | GO PLACE 상태 |
|---|---|---|---|
| 1 | **확인 수단을 준다** — 테스트, 화면 캡처, 빌드 결과로 AI가 스스로 맞았는지 보게 한다. Boris Cherny는 이것이 결과 품질을 가장 크게 올린다고 했다 | AI는 그럴듯한 틀린 답을 자신 있게 낸다. 스스로 확인할 수 있으면 고쳐 가며 맞힌다 | ✅ qa-tester, Playwright, "빌드 성공 ≠ 기능 정상" |
| 2 | **기억 문서를 키운다** — CLAUDE.md(OpenAI는 AGENTS.md)에 규칙을 적고, **AI가 실수할 때마다 한 줄 추가**한다. 팀 전체가 같은 문서를 쓴다 | 한 번 고친 실수가 다시 안 나온다 → 시간이 갈수록 좋아지는 복리 효과 | 🟡 CLAUDE.md는 있음. "교정 → 규칙"을 습관으로 → **CLAUDE.md 12절 새로 추가** |
| 3 | **계획 먼저, 실행은 나중** — 큰 일은 "먼저 계획만 보여 줘"로 시작해 방향을 맞춘 뒤 실행 | 방향이 틀린 채 많이 만들면 되돌리는 비용이 크다 (GO LIFT v0.2가 예) | 🟡 → 아래 "요청 틀" 사용 |
| 4 | **컨텍스트 엔지니어링** — 필요한 정보를 딱 맞게 준다. 너무 적으면 추측하고, 너무 많으면 흐려진다 (Karpathy) | AI의 답은 받은 정보의 질을 넘지 못한다 | ✅ status.md, links.md, 프로젝트 GitHub 동기화 |
| 5 | **여러 AI를 동시에** — 세션 여러 개를 나란히 돌리고, 사람은 관리자처럼 검토만 한다 | 사람의 시간이 병목. 기다리는 시간을 없앤다 | 🟡 → 대표가 세션 2개 나눠 쓰기 (아래 4절) |
| 6 | **반복은 도구로** — 같은 요청을 몇 번 하면 슬래시 명령·스킬·훅·예약 작업으로 만든다 | 매번 설명하는 시간이 0이 된다 | ✅ 주간 회의 예약 작업, 역할 카드 / **릴스 인사이트 스킬 새로 추가** |
| 7 | **사람은 판단과 취향을 지킨다** — "AI를 짧은 줄에 묶어 둔다"(Karpathy). 작은 단위로 맡기고 결과를 직접 본다 | AI는 무엇이 중요한지 모른다. 고르는 건 사람 | ✅ CLAUDE.md 1-2 "선택은 대표가 한다" |

**결론 (솔직하게):** GO PLACE는 이미 7개 중 4개를 갖추고 있다. 남은 차이는 기능이 아니라 **습관**(2·3·5번)이다.
그리고 지금 GO PLACE의 진짜 병목은 AI 쪽이 아니라 **사람 쪽**(테스터 반응, 릴스 고객 반응, 대표의 시간)이다.
AI를 더 잘 쓰는 것의 목표는 대표의 시간을 그쪽(고객 만나기, 결정, 운동)에 더 쓰게 하는 것이다.

## 3. 바로 쓰는 요청 틀 (휴대폰에 저장해 두고 붙여 넣기)

큰 일을 맡길 때 (습관 3·4):
```
목표: [무엇을 위해]
끝난 모습: [이게 되면 끝 — 예: 휴대폰에서 버튼 누르면 등급이 나옴]
하지 말 것: [예: 기존 기록 지우기, 유료 기능]
먼저 계획만 3줄로 보여 주고, 내가 "진행"하면 시작해.
```

AI가 틀렸을 때 (습관 2):
```
이건 틀렸어: [무엇이]
원래 원하는 건: [무엇]
다음부터 안 틀리게 규칙 문서에 한 줄 추가해 줘.
```

결과를 받았을 때 (습관 1):
```
이거 어떻게 확인했어? 확인 못 한 부분은 뭐야?
```

## 4. 휴대폰에서 생산성을 크게 올리는 습관

1. **음성 입력**: 휴대폰 키보드의 마이크 버튼으로 말로 요청한다. 타자보다 3~4배 빠르다(일반적인 말하기·타자 속도 차이). 길게 말해도 AI가 정리한다.
2. **세션 나누기**: Claude Code 세션을 일 종류별로 나눈다 → 한 세션이 길어지면 앞 내용을 요약하느라 흐려진다.
   - 세션 A: 체력특급 / 세션 B: GO LIFT / 세션 C: 회사 문서·주간 회의
   - 한 세션이 일하는 동안 다른 세션에 다음 일을 맡긴다 (습관 5)
3. **새 세션은 무섭지 않다**: 기억은 저장소 문서(CLAUDE.md, status.md)에 있다. 대화가 너무 길어졌으면 새로 열어도 된다.
4. **생각은 프로젝트, 실행은 Claude Code**: 책 읽고 떠오른 생각은 프로젝트 "GO PLACE 본부"에서 정리 → 결정이 나면 Claude Code에 한 줄로 전달 (`docs/ai-team.md` 8절).

## 5. Claude 기능 지도 (무엇을 언제)

| 기능 | 언제 쓰나 | GO PLACE에서 |
|---|---|---|
| Claude Code | 코드·문서·이미지 만들기, PR | 매일 |
| 서브에이전트 (역할 카드) | 검토를 다른 눈으로 (규정·품질) | `.claude/agents/` |
| 스킬 | 순서가 정해진 반복 일 | `.claude/skills/` (릴스 인사이트) |
| 예약 작업 | 정해진 때 스스로 일하기 | 일요일 주간 회의, 테스트 7·13·14일 알림 |
| 아티팩트 | 휴대폰에서 보는 화면 | 상황판 |
| 프로젝트 + GitHub 동기화 | 깊게 생각하기, 책 메모 | GO PLACE 본부 |
| 커넥터 (Google Drive·Sheets 등) | 다른 서비스의 자료를 AI가 직접 읽기 | 아직 안 씀. 쓰려면 개인정보(이메일 등) 빼는 규칙 먼저 |

## 6. 대표가 배울 원리 (과학)

- **AI는 다음 말을 예측하는 기계다.** 그래서 받은 정보(컨텍스트)가 좋으면 답이 좋고, 모르면 그럴듯하게 지어낸다 → 확인 수단과 "모르면 모른다고 해" 규칙이 필요하다.
- **AI는 기억이 없다.** 대화가 끝나면 잊는다 → 기억은 문서에 둔다. 문서가 회사의 뇌다.
- **AI는 빠르지만 무엇이 중요한지 모른다.** 중요한 것을 아는 건 고객을 만나는 사람이다 (CLAUDE.md 1-2).
