# 릴스 인사이트 정리 (3번 반복된 일 → 도구화, 2026-11-22)

대표가 릴스 1편·2편·3편마다 같은 일을 맡겼다. `docs/ai-team.md` 9절 ① "세 번 반복하면 도구로"에 따라 순서를 고정한다.

## 순서

1. **캡처에서 숫자만 옮긴다.** 조회(계정 수), 건너뛰기 비율, 평균 시청 시간, 연령 상위 2개, 팔로워 아닌 사람 비율, 프로필 방문, 댓글·공유·저장.
   - 캡처에 없는 숫자는 `?`로 둔다. 추측해서 채우지 않는다.
   - 개인 계정 이름·댓글 단 사람 이름은 옮기지 않는다.
2. **이전 편과 표로 비교한다.** 기준 표: goplace `docs/status.md` 3절 "인스타 실험".
3. **배운 것은 한 가지만** 뽑는다. "확인됨"(숫자로 보임)과 "추정"(원인 가설)을 나눠 쓴다.
   - 표본이 작다(수백 명)는 점을 늘 함께 말한다. 한 편으로 결론 내지 않는다.
4. **기록한다** (PR 하나):
   - goplace `docs/status.md` 3절 표에 한 줄
   - 체력특급 `docs/testing/reels-plan.md` 해당 편 절에 "N편에서 배운 것"
   - 상황판 아티팩트 `reels` 데이터셋 (있으면)
5. **다음 편 제안은 바꿀 것 하나만.** 한 번에 여러 개를 바꾸면 무엇이 효과였는지 모른다.
   - 고객 = 입대 예정자 + 현역 장병 (2026-11-22 결정)에 맞는지 확인
   - 밖으로 나가는 문구는 compliance-guard 기준(비공식 표시, 부대 정보 없음, 영리 없음)으로 점검
6. **대표에게 보고**: 표 → 배운 것 1개 → 다음 편 제안 1개 → 체크포인트(링크·시간·확인법). 휴대폰 한 화면.

## 보는 숫자의 뜻 (대표에게 가르칠 것)
- **건너뛰기 비율**: 첫 1~2초에 넘긴 비율. 첫 장(커버) 성적표
- **평균 시청 시간 ÷ 길이**: 끝까지 봤는지. 알고리즘이 더 퍼뜨릴지 정하는 핵심 신호(추정, 공개 설명 기준)
- **연령**: 우리 고객(18~24세 중심)에게 닿았는지
- **프로필 방문 → 웹 방문**: 실제 행동. 조회수보다 중요
